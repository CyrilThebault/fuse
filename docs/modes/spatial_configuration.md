# Spatial configuration

The spatial configuration defines how the hydrologic model is applied
across the landscape. FUSE supports two spatial configurations:
catchment mode, in which the model is applied to a single catchment, and
grid mode, in which the model is applied independently to each grid cell
in a spatial domain. Both configurations optionally support elevation
bands to improve the representation of snow accumulation and melt.

The spatial configuration is specified through entries in the control
file.

> **Note**
>
> Grid-mode support is currently under active development in the FUSE
> v2 code base. Until this work is complete, users requiring distributed
> simulations should use the legacy FUSE implementation available at
> <https://github.com/naddor/fuse>.

## Catchment mode

Catchment mode is the original configuration of FUSE. The model is
applied to a single spatial unit representing an entire catchment and is
intended for conceptual rainfall–runoff modelling.

## Grid mode

Grid mode applies FUSE independently to every grid cell in a spatial
domain, enabling large-domain hydrologic simulations driven by gridded
meteorological forcing. Each grid cell has its own forcing data and
parameter values and is simulated independently.

FUSE does not simulate lateral exchange of water between neighbouring
grid cells. If lateral routing is required, runoff generated by FUSE can
be routed through a river network using an external routing model such
as [mizuRoute](https://mizuroute.readthedocs.io/en/main/).

## Elevation bands

Both catchment mode and grid mode represent each spatial unit as a
lumped hydrologic model. To improve the representation of snow
accumulation and melt, each spatial unit may be subdivided into
elevation bands. The snow module is evaluated independently for each
elevation band, while the remaining hydrologic processes continue to
operate on the lumped spatial unit.

Elevation bands are required when the snow module is active because they
provide the topographic variation in temperature and precipitation
needed to represent snow processes. See
[Model inputs](../files/input_files.md) for details.
